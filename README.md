A terminal portfolio, blog, and developer hub rendered by Rust on Cloudflare Workers.

Live demo: **[https://scrov.app](https://scrov.app)**

## Features

- **Distro & Terminal Theming**: Switch between 26 Linux, BSD and other system palettes (Debian, Arch, Ubuntu, Kali, Fedora, Void, NixOS, etc.) with zero flicker.
- **Server-rendered in Rust**: Every page is a Leptos component rendered to HTML at the edge. No client-side framework is shipped.
- **Hypermedia interactions**: htmx swaps in HTML fragments (project details, blog filter); hyperscript handles menus and selection states.
- **In-browser lab** (`/lab/`): query the site's data with Postgres (PGlite) and script it with Lua (Fengari), both running in the visitor's tab.
- **YAML-Driven Content**: Profile, projects and system definitions live in `content/data.yml` and `content/systems.yml`; posts are Markdown in `content/blog/`.
- **Agent-friendly**: `llms.txt`, RSS, sitemap, and a Markdown version of every page (`Accept: text/markdown`, or the `.md` URLs).
- **WebMCP tools**: in a browser that exposes `document.modelContext`, each page registers tools an agent can call instead of scraping: read the profile and posts, switch the theme, filter the blog, run SQL or Lua in the lab.
- **One app, three hosts**: the same router runs on Cloudflare Workers, on a native server behind Pingora, and inside a Tauri desktop app.

## Lab

- **[Intent Lab](https://scrov.app/lab/intent/)**: a prototype of brain–computer interface cursor control. A simulated decoder runs in a Web Worker. Its output goes through a One Euro filter and a tunable spring to the drawn cursor. A timed grid task reports bits per second and input-to-frame latency against a 15 ms budget. Write-up: [`docs/intent-lab.md`](docs/intent-lab.md). Tests: [`scripts/intent-core.test.ts`](scripts/intent-core.test.ts).
- **[scrov platform](https://scrov.app/platform/)**: a planned voice agent that sends one spoken request to many devices as WebMCP tool calls. Spec: [`/wiki.md`](public/wiki.md). Design system: [`DESIGN.md`](DESIGN.md).

## Tech Stack

| Piece | Role |
| --- | --- |
| [Leptos](https://leptos.dev) (SSR only) | Pages and components |
| [shtml](https://github.com/swlkr/shtml) | HTML fragments returned to htmx |
| [htmx](https://htmx.org) + [hyperscript](https://hyperscript.org) | Interactivity without a client framework |
| [webmcp-rs](https://github.com/hauju/webmcp-rs) | WebMCP tool registration from a small Leptos island in the browser |
| [PGlite](https://pglite.dev) + [fengari-web](https://github.com/fengari-lua/fengari-web) | Postgres and Lua in the browser (lab page) |
| [Tailwind CSS 4](https://tailwindcss.com) | Styling, built with the Tailwind CLI |
| [workers-rs](https://github.com/cloudflare/workers-rs) | Cloudflare Workers entry point (WebAssembly) |
| [Pingora](https://github.com/cloudflare/pingora) | Reverse proxy for self-hosting |
| [Tauri 2](https://tauri.app) | Desktop shell with the server embedded |
| [Bun](https://bun.sh) | Asset pipeline, sync script and its tests |

Pingora and Tauri are native-only. They wrap the same site for self-hosting and desktop use and are not part of the Worker that Cloudflare runs.

## Project Structure

```
.
├── crates/
│   ├── app/                  # The site: config, content, Leptos pages, shtml fragments, router
│   ├── client/               # Browser-side Leptos island: registers the WebMCP tools (WebAssembly)
│   ├── worker/               # Cloudflare Workers entry point (compiled to WebAssembly)
│   ├── server/               # Native axum server: static files + the same router
│   └── proxy/                # Pingora reverse proxy in front of the native server
├── src-tauri/                # Tauri desktop shell embedding the native server
├── content/
│   ├── blog/                 # Posts (Markdown with front matter)
│   ├── logos/                # fastfetch ASCII logos, one per distro
│   ├── data.yml              # Profile, host, and contact data
│   ├── systems.yml           # Distro theme definitions
│   └── config.json           # Generated by `bun run sync`
├── public/                   # Static files; js/ holds the hand-written scripts
├── prebuilt/                 # Committed build outputs (Worker bundle, WebMCP client) so deploys skip the Rust compile
├── style/input.css           # Tailwind entry point
├── scripts/
│   ├── assets.ts             # Copies vendor JS and fonts into public/, fetches missing logos
│   ├── build-client.sh       # Builds crates/client into public/pkg/client with wasm-bindgen
│   ├── update-prebuilt.sh    # Compiles from source and refreshes prebuilt/
│   ├── build-worker.sh       # Full Worker build (used by wrangler and CI)
│   ├── sync.ts               # YAML + GitHub -> content/config.json
│   └── sync.test.ts          # Bun unit tests for sync logic
├── app/
│   ├── angular/webmcp/       # Angular pizzeria app exposing WebMCP tools
│   ├── angular/webmcp-example/ # Minimal Angular + @mcp-b/global WebMCP example
│   └── nx/                   # Nx workspace (NestJS api, Angular SSR xui)
├── Cargo.toml                # Rust workspace
├── rust-toolchain.toml       # Pinned Rust toolchain
├── package.json              # Scripts and browser dependencies
└── wrangler.toml             # Cloudflare Workers configuration
```

## Getting Started

### Prerequisites

- [rustup](https://rustup.rs); it installs the toolchain pinned in `rust-toolchain.toml`
- [Bun](https://bun.sh) (v1.x)
- For the desktop app only: the [Tauri prerequisites](https://tauri.app/start/prerequisites/) and `cargo install tauri-cli`

### Installation

```bash
bun install
```

### Development

```bash
bun run dev          # builds CSS + assets, then serves http://127.0.0.1:3000 natively
bun run preview      # full Worker build, served by `wrangler dev` in the Workers runtime
```

After changing Rust, restart `bun run dev`. After changing classes or `style/input.css`, run `bun run css`.

### Sync GitHub Projects

Regenerate `content/config.json` from the YAML files and GitHub:

```bash
bun run sync
```

### Tests

```bash
bun run check        # build:web, cargo test, bun test
```

### WebMCP tools

`crates/client` is a Leptos component compiled to WebAssembly and mounted into the footer. It registers tools with [webmcp-rs](https://github.com/hauju/webmcp-rs), which ties each tool to the component that offers it:

| Where | Tools |
| --- | --- |
| Every page | `get_profile`, `list_projects`, `list_posts`, `read_post`, `list_themes`, `set_theme` |
| Blog index | `filter_blog` |
| Lab | `run_sql`, `run_lua` |

Tools only appear in a browser with WebMCP: Chrome 149 or newer with `chrome://flags/#enable-webmcp-testing`, or through the origin trial. Elsewhere the footer shows `webmcp: off` and nothing is registered. Argument schemas are derived from the Rust argument types, and `cargo test -p scrov-client` validates every tool descriptor without a browser.

The site and the client enable different Leptos features (`ssr` and `csr`), so build, lint and test them in separate cargo invocations, as the scripts and CI do.

### Deployment

Pushing to `main` deploys through Cloudflare's Git integration (Workers Builds). `.github/workflows/deploy.yml` is a second path that runs `wrangler deploy` only when the repository has `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets. To deploy by hand:

```bash
bun run deploy       # builds everything, then `wrangler deploy`
```

`wrangler deploy` runs `scripts/build-worker.sh`, which prepares `public/` and the Worker bundle.

The Worker and the WebMCP client are also committed in [`prebuilt/`](prebuilt/README.md), with a hash of the sources they were built from. When that hash matches, the build copies them and needs no Rust toolchain, so a deploy takes seconds. When the sources have changed, the script compiles instead, installing rustup, the pinned toolchain and the build tools if they are missing. On `main`, the `Prebuilt artifacts` workflow rebuilds and commits `prebuilt/` whenever the sources change; `bun run update-prebuilt` does the same locally.

### Self-hosting with Pingora

```bash
bun run build:web
cargo run --release -p scrov-proxy    # http://0.0.0.0:8080
```

The proxy starts the site in-process on a loopback port and fronts it with Pingora. `SCROV_LISTEN`, `SCROV_UPSTREAM` and `SCROV_PUBLIC_DIR` change the defaults.

### Desktop app

```bash
cargo tauri dev      # or: cargo run -p scrov-desktop
cargo tauri build
```

The Tauri shell runs the server inside its own process on a free port and points the webview at it, following [tauri-leptos-ssr](https://github.com/codeitlikemiley/tauri-leptos-ssr).
